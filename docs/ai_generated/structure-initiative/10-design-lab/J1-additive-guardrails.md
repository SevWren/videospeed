## 3. What Moves and What Stays

**Nothing moves.** This is a purely additive design. No source file under `src/`, no `manifest.json`, no `LICENSE`, no `PRIVACY.md`, no existing file under `tests/` is touched.

### Existing files this design edits

Per charter §5 allowed writes, only two existing files may be edited:

1. **`CLAUDE.md`** — Add four pointer lines (≤10 lines total added):
   - Pointer to `AGENTS.md` as the primary agent entry point
   - Pointer to `docs/ai_generated/protected-behaviors/registry.md`
   - Pointer to `docs/ai_generated/modules/registry.md`
   - Note that `check:structure`, `check:docs`, `check:citations` are available as `npm run` commands

2. **`CONTEXT.md`** — Add a cold-start preamble (≤8 lines) at the top of the file: a brief orientation sentence and a "jump to" index pointing to AGENTS.md, the PB registry, and the module registry. Does not alter any existing term definition.

3. **`package.json`** — Add `check:*` and `map:*` script entries only (allowed per charter §5):
   - `"check:structure": "node scripts/check-structure.mjs"`
   - `"check:docs": "node scripts/check-docs.mjs"`
   - `"check:citations": "node scripts/check-citations.mjs"`
   - `"map:repo": "node scripts/gen-repo-map.mjs"`

## 4. What Each New File Does

**`AGENTS.md`** — Root-level agent entry file (≤200 lines) that surfaces critical invariants within 2 hops: points to PB registry, module load-order contract, window.VSC namespace, task-suite runbooks, and ADR index.

**`docs/ai_generated/REPO_MAP.md`** — Generated flat map of every src file with its module name, WAR status, and nearest test; produced by `gen-repo-map.mjs` and committed as a stable snapshot.

**`docs/ai_generated/protected-behaviors/registry.md`** — Structured table of all 14 protected behaviors (PBID, rule, code path:line, test path or "untestable: reason"); the single source of truth for PB invariants.

**`docs/ai_generated/protected-behaviors/contract-stubs.md`** — Prose specifications (not code) for the five P2–P6 contract tests: what each test must assert, which JSDOM limitation applies to P4/P6, and what a real-Chrome test would verify.

**`docs/ai_generated/modules/registry.md`** — Single authoritative list of all modules in injection order, their WAR glob match, their `window.VSC.*` export name, and their test file; the single source of truth consumed by `check:structure`.

**`docs/ai_generated/modules/window-vsc-namespace.md`** — Explicit map of every `window.VSC` key, the module that writes it, and the modules that read it; prevents agents from introducing ESM imports between page-world modules.

**`docs/ai_generated/adr/ADR-0001-no-esm-imports.md`** — Records the architectural decision that page-world modules communicate via `window.VSC`, not ESM imports, and the reason (MV3 page-world isolation).

**`docs/ai_generated/adr/ADR-0002-load-order-contract.md`** — Records that `injector.js` load order is a contract, lists the exact sequence, and explains why reordering causes undefined-global failures.

**`docs/ai_generated/adr/ADR-0003-sentinel-pattern.md`** — Records the `{pending:true, _cancelled:false}` sentinel, why it exists (async double-attach race), and what breaks if it is removed.

**`docs/ai_generated/adr/ADR-0004-patch-canvas.md`** — Records the `_patchCanvas` compositing indirection, why direct `putImageData` on the composite canvas produces black artifacts, and which frames trigger the issue.

**`docs/ai_generated/adr/ADR-0005-gif-file-fetcher.md`** — Records why `gif-file-fetcher.html` is an iframe proxy at a `chrome-extension://` origin, why direct XHR fails for `file://` GIFs, and what would break if the file were moved.

**`docs/ai_generated/migration-tickets/MT-001-payload-validation.md`** — Migration ticket: add payload schema validation to `VSC_SAVE_SETTINGS` handler (pre-existing security defect; requires `src/` edit; human-gated).

**`docs/ai_generated/migration-tickets/MT-002-privacy-md-cache-claim.md`** — Migration ticket: correct PRIVACY.md `cache: force-cache` claim to `cache: 'default'` before next Web Store submission; human-gated.

**`docs/ai_generated/migration-tickets/MT-003-dead-module-loader.md`** — Migration ticket: remove `src/module-loader.js` after characterization test confirms it is dead code; requires manifest.json change; human-gated.

**`docs/ai_generated/migration-tickets/MT-004-runtime-file-moves.md`** — Migration ticket: index of all planned runtime file reorganizations deferred from this initiative; prerequisite checklist before any future restructuring branch.

**`scripts/gen-repo-map.mjs`** — Node ESM script that reads `manifest.json` WAR entries and `src/` directory, outputs `docs/ai_generated/REPO_MAP.md` with module table.

**`scripts/check-structure.mjs`** — Node ESM check script: verifies that injector.js load order, manifest.json WAR list, and `docs/ai_generated/modules/registry.md` all agree; exits non-zero with diff on mismatch.

**`scripts/check-docs.mjs`** — Node ESM check script: verifies that every file path cited in agent-facing docs exists at the given path; exits non-zero and lists broken citations.

**`scripts/check-citations.mjs`** — Node ESM check script: verifies that every PBID cited in registry rows has a corresponding code path that resolves, and every test path in the registry exists; exits non-zero with details.

**`tests/unit/protected-behaviors/pb-p2-vsc-gif-ignore.test.js`** — Contract test for P2: asserts that `vscGifIgnore` flag is bypassed when `src` attribute changes, and that `_vscTeardownSrc` is reset correctly.

**`tests/unit/protected-behaviors/pb-p3-sentinel-pattern.test.js`** — Contract test for P3: asserts that a second `create()` call during a pending async window returns the sentinel and does not double-attach a controller.

**`tests/unit/protected-behaviors/pb-p4-patch-canvas.test.js`** — Contract test for P4: asserts that `_drawFrame` routes through `_patchCanvas` and that a spy on `putImageData` is never called directly on the composite canvas.

**`tests/unit/protected-behaviors/pb-p5-loop-count-null.test.js`** — Contract test for P5: asserts that `loopCount = null` and `loopCount = undefined` from the decoder both resolve to `0` (infinite loop), not termination.

**`tests/unit/protected-behaviors/pb-p6-disposal2-bg-color.test.js`** — Contract test for P6: asserts that `disposal=2` triggers `fillRect` with `_bgColor`, not `clearRect`; verifies no transparent/black background regression.

**`.claude/agents/implement.md`** — Subagent definition for implementation tasks: pre-conditions checklist (read PB registry, run check:structure, run check:citations before modifying any src file).

**`.claude/agents/diagnose.md`** — Subagent definition for diagnosis tasks: instructs agent to start from PB registry and REPO_MAP before reading any source file.

## 8. Migration Path

**This design has no migration.** All changes are additive. Deleting the files added by J1 returns the repo to byte-identical baseline on the protected surface.

### What a future initiative would need to do for runtime file moves

If a follow-on initiative wants to reorganize `src/` (e.g., consolidate modules, add a build step, extract a `dist/` output):

1. **Prerequisite**: All P2–P14 contract tests must pass at green before any file move (MT-004 prereq checklist item 1).
2. **Prerequisite**: PRIVACY.md cache claim must be corrected (MT-002) before any Web Store submission post-restructure.
3. **Prerequisite**: `VSC_SAVE_SETTINGS` payload validation must be implemented (MT-001) if the restructure touches the settings bridge.
4. **For every moved src file**: Update `manifest.json` WAR list, update `injector.js` load sequence, update `modules/registry.md` — then run `check:structure` to confirm all three agree.
5. **For dead code removal**: Remove `src/module-loader.js` only after `module-integration.test.js` is extended to assert it is unreachable (MT-003 prereq).

Relevant migration tickets: MT-001, MT-002, MT-003, MT-004 (all under `docs/ai_generated/migration-tickets/`).

## 11. Risks and Gaps

### What cannot be achieved by additive-only

**R1 — Source file navigation cost**: The largest source files (`gif-controller.js` ~8k tokens, `inject.js` ~5k tokens, `action-handler.js` ~4k tokens) remain monolithic. An agent fixing a GIF rendering bug still reads the full `gif-controller.js`. Only runtime file splitting (out of scope) would reduce this. Estimated token waste: ~8k per GIF task.

**R2 — `VSC_SAVE_SETTINGS` payload validation gap**: C-4 prohibits replicating this pattern; J1 documents it (MT-001). But the vulnerability exists until a follow-on initiative edits `src/`. Any new CustomEvent added by agents who read the pattern and replicate it is a security regression.

**R3 — Dead code exposure**: `src/module-loader.js` remains web-accessible and ships in the extension zip. J1 documents this (MT-003) but cannot remove it without a `manifest.json` change (ZERO-DIFF surface). Risk: confused agents reading it as an active module loading system.

**R4 — PRIVACY.md false claim**: Cannot be fixed in this initiative (ZERO-DIFF). MT-002 flags it for human action before the next Web Store submission.

**R5 — `.gitignore` and `.claude/` persistence**: C-20 requires removing `.claude/` from `.gitignore` before `.claude/agents/` definitions persist across fresh clones. J1 adds `.claude/agents/implement.md` and `.claude/agents/diagnose.md` but cannot enforce the `.gitignore` fix (that edit is not on the allowed writes list in charter §5 as written). This is a pre-condition that must be addressed by Team L before scaffold is committed.

**R6 — Contract test coverage gaps for P9–P14**: Only P2–P6 receive new contract tests. P9 (blacklist), P10 (settings persistence), P11 (action dispatch safety), P12 (site handler exclusion), P13 (speed range enforcement), P14 (GIF memory budget) have registry rows but no new tests added. These are SHOULD items; full coverage requires a follow-on test initiative.

**R7 — Check script drift**: `docs/ai_generated/modules/registry.md` and `docs/ai_generated/protected-behaviors/registry.md` are committed static documents. They will drift from code if maintainers forget to update them. `check:structure` and `check:citations` mitigate this for paths, but not for semantic content changes (e.g., a behavior is modified without updating its PB description). Full mitigation requires human discipline or a more invasive source-of-truth approach.

### What would require a follow-on initiative

- Source file splitting / module boundary extraction → requires touching `src/**` and `manifest.json`
- Removing `src/module-loader.js` → requires `manifest.json` change
- Fixing `VSC_SAVE_SETTINGS` payload validation → requires `src/` edit
- Correcting PRIVACY.md cache claim → requires `PRIVACY.md` edit (human-gated)
- Firefox MV2 manifest delta → requires `manifest.json` change
- Build pipeline / dist/ output → requires WAR + getURL() changes
- Contract tests for P9–P14 → additive, but deferred per priority
